# PIX Key Manager

A prototype internal manager for PIX keys, built with Java 27 and Spring Boot 4.1.2.

> **Important:** this is an internal prototype. Registering a key here does **not** register it in the DICT (Central Dictionary of PIX keys) and does **not** make it ready to receive payments. Records are stored with the state `INTERNAL_RECORD`.
>
> The prototype has no authentication or authorization yet. Use **only fictitious data**.

## Features

- Register a PIX key of type `CPF`, `CNPJ`, `EMAIL`, `PHONE` or `RANDOM` (UUID).
- Format validation per key type (CPF/CNPJ are checked by format only; check digits are not verified).
- Masked key value in the API response to limit exposure of personal data.
- Records persisted in an embedded H2 database.

### Planned, not yet implemented

Per the specification in [`doc/especificacao-gerenciador-chaves-pix.md`](doc/especificacao-gerenciador-chaves-pix.md):

- Listing and viewing registered keys (H2).
- Removing a key (H3).

Out of scope for this version: DICT/core integration, authentication, and quantity or regulatory limits.

## Getting started

### Prerequisites

- JDK 27

No Maven installation is required; use the wrapper.

### Build and test

```bash
./mvnw test
```

On Windows (PowerShell or Command Prompt), use `mvnw.cmd` instead.

### Run

```bash
./mvnw spring-boot:run
```

The application starts on the default port `8080`.

```bash
./mvnw package
```

## API

### Register a PIX key

`POST /api/pix-keys`

Request body:

```json
{
  "type": "EMAIL",
  "value": "fulano@example.com"
}
```

`type` must be one of `CPF`, `CNPJ`, `EMAIL`, `PHONE`, `RANDOM`.

Accepted formats:

| Type     | Accepted format                                                                 |
|----------|---------------------------------------------------------------------------------|
| `CPF`    | 11 digits, or `000.000.000-00`                                                  |
| `CNPJ`   | 14 digits, or `00.000.000/0000-00`                                              |
| `EMAIL`  | Simple syntax `local@domain.tld`                                                |
| `PHONE`  | Optional leading `+`, 8–20 characters from digits, spaces, `()`, `.`, `-`; at least 8 digits |
| `RANDOM` | UUID, e.g. `123e4567-e89b-12d3-a456-426614174000`                               |

Success response (`201 Created`):

```json
{
  "id": 1,
  "type": "EMAIL",
  "maskedValue": "***@***",
  "status": "INTERNAL_RECORD"
}
```

Masking rules:

| Type            | Masked value             |
|-----------------|--------------------------|
| `CPF`, `CNPJ`   | `***` + last 2 characters |
| `PHONE`         | `***` + last 2 characters |
| `EMAIL`         | `***@***`                |
| `RANDOM`        | `***` + last 4 characters |

Error responses (`400 Bad Request`, RFC 9457 `ProblemDetail`) are returned when:

- `type` or `value` is missing or blank.
- `value` does not match the format for the given type.
- The request body is malformed or contains an unknown `type`.

## Configuration

Configuration lives in `src/main/resources/application.yaml`:

```yaml
spring:
  application:
    name: pix-key-manager
```

The database schema is defined in `src/main/resources/schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS pix_key_records (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    key_type VARCHAR(20) NOT NULL,
    key_value VARCHAR(255) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```
